# Caption Style Picker ("Altyazı seç") — Design

**Date:** 2026-07-14
**Status:** Approved (design), pending implementation

## Goal

Add a caption-style selector to the Home `MediaComposer`, matching the existing
Avatar / Ses (voice) / Geçiş (transition) picker pattern: a **chip button** that
opens a **modal** showing **hundreds of caption-style presets** with live-looking
previews, search, and a "Filtrele" sheet. Also extend the worker with new caption
render kinds so the variety is genuinely new, not just recolored.

## Background / current state

Everything downstream of the picker already exists:

- **Schema** (`apps/web/src/lib/schemas.ts`): `captionStyle` enum + `captionFont` +
  `captionColor`.
- **Worker** (`apps/worker/sentezy_worker/compose.py`): `_CAPTION_STYLES` with 7
  engine styles (`karaoke`, `tiktok`, `beast`, `hormozi`, `boxed`, `clean`,
  `keyword`) driven by a `kind` field (`karaoke`, `wordpop`, `phrase`, `box`,
  `keyword`). Burns captions via libass, using bundled fonts in `apps/worker/fonts`.
- **Pipeline** (`pipeline.py`): passes `style` / `font` / `color` straight through
  to `build_captions_ass`; unknown `style` falls back to `karaoke`.
- **API**: stores `options` as opaque JSON (`Prisma.InputJsonValue`) — no
  server-side enum, so no API change is needed for new styles.
- **Preview** (`ReelPreview.tsx`): already renders captions word-by-word for a
  given `{captionStyle, captionFont, captionColor}`.
- **Wizard** (`CreateWizard.tsx`): seeds `captionStyle/Font/Color` when resuming a
  draft, and consumes the `sentezy:pending-create` payload from the Home composer.

**The only gap:** `MediaComposer` has no caption picker and its `pending-create`
payload omits caption fields, so new videos always default to karaoke/yellow.

## Bundled fonts (the preset font set)

`apps/worker/fonts`: Anton, Archivo Black, Bebas Neue, Fredoka, General Sans,
Inter, Kanit, Montserrat, Oswald, Poppins, Rubik, Sora, Teko (13 families). All are
Google Fonts except General Sans (Fontshare). Presets may only use these fonts so
**tile preview == burn-in**. The web app self-hosts these families via `@font-face`
(reusing the same TTF/OTF files under `apps/web/public/fonts/`) so the picker
previews render in the real fonts.

## Components

### 1. New worker engine kinds — `compose.py`

Add 3 new `kind` renderers to `_CAPTION_STYLES`, each ASS/libass-feasible and
visually distinct from the existing 7:

- **bubble** — each word in its own opaque rounded pill; the spoken word's pill uses
  the accent color. Distinct from `boxed` (whole-phrase box). Implemented with
  per-word `BorderStyle 3` backdrop segments.
- **highlight** — phrase in plain white; the spoken word gets a filled "marker
  swipe" background rectangle in the accent color behind it.
- **typewriter** — words appear one-by-one, cumulatively building the phrase, no
  dimmed upcoming-word preview. Clean/mono feel.

New style keys (`bubble`, `highlight`, `typewriter`) are added to `_CAPTION_STYLES`
with tuned `chunk/scale/min_size/bold/outline/shadow/kind`. A new branch in the
Dialogue-emission loop handles each new `kind`.

### 2. Preset catalog — new `apps/web/src/lib/captionStyles.ts`

```ts
export type CaptionEngine =
  | "karaoke" | "tiktok" | "beast" | "hormozi" | "boxed" | "clean" | "keyword"
  | "bubble" | "highlight" | "typewriter"; // 10 families

export type CaptionPreset = {
  id: string;      // stable slug, e.g. "karaoke-bebasneue-yellow"
  name: string;    // display, e.g. "Karaoke · Bebas · Sarı"
  base: CaptionEngine;
  font: string;    // one of the 13 bundled family names
  color: string;   // accent hex
  family: string;  // filter grouping label (Turkish)
};

export const CAPTION_PRESETS: CaptionPreset[];
```

Generated by cross-product at module load:

- **families**: the 10 engine kinds.
- **fonts**: the 13 bundled families.
- **accent colors**: ~12-color palette (brand yellow first, then a curated set).
  Color varies only for accent-using families (karaoke, tiktok, beast, hormozi,
  boxed, keyword, bubble, highlight); non-accent families (clean, typewriter) vary
  font only (color fixed white).

This yields several hundred presets. Each maps directly to
`{captionStyle: base, captionFont: font, captionColor: color}`. The current default
(karaoke / General Sans / `#FFD54A`) is the default preset.

### 3. Reusable sample renderer — new `apps/web/src/components/CaptionSample.tsx`

Extract the word-by-word caption rendering currently inline in `ReelPreview` into
one component:

```ts
<CaptionSample base font color text? animate? />
```

- Renders a sample phrase for `{base, font, color}`.
- **Static** by default with the active word already "popped" (so a still tile looks
  correct).
- **Animates** the karaoke/pop/typewriter sweep only when `animate` is true
  (hover / selected tile / the live ReelPreview).
- `ReelPreview` is refactored to render captions through `CaptionSample`, so the
  picker tiles and the real preview stay pixel-consistent. This is the isolation
  improvement: one place owns caption visual rendering.

### 4. Modal + chip in `MediaComposer.tsx`

- New **"Altyazı"** chip beside Avatar / Ses / Geçiş: shows the selected preset's
  short name, **disabled until `script` is non-empty** (existing show-but-disable
  rule). Default = the karaoke/yellow preset.
- **Modal** mirrors the voice modal:
  - Search box (matches over `name` / `family` / `font`).
  - **"Filtrele" sheet** (nested, not inline) with: family pills (Karaoke,
    Hormozi, Bubble, Highlight, Typewriter, …), a font dropdown (`Dropdown`
    component, reused), and accent-color swatches. Same `V_*`-style constants and
    active-filter count / clear-all as the voice filters.
  - **Grid of `CaptionSample` tiles** (static). Hovered/selected tile passes
    `animate`. Selected tile shows a check/ring like avatar/voice selection.
  - **Incremental reveal** via an `IntersectionObserver` sentinel (same technique
    as the infinite voice list) — render the first N tiles, grow on scroll — so
    hundreds stay smooth without a virtualization dependency.
- Selecting a preset sets `captionStyleId`; derive `{style, font, color}` from the
  catalog for the payload.

### 5. Wiring `pending-create` → wizard

- `MediaComposer` stashes `caption: { style, font, color }` in the
  `sentezy:pending-create` payload (alongside `media/script/avatar/voice`).
- `CreateWizard`'s pending-create effect reads it and calls
  `setValue("captionStyle" | "captionFont" | "captionColor", …)`. Extend the
  payload type there accordingly.

## Data flow

```
MediaComposer (pick preset)
  → captionStyleId → {style,font,color}
  → sessionStorage["sentezy:pending-create"].caption
→ CreateWizard seeds captionStyle/Font/Color into the form
→ buildOptions → options.captions = {enabled, style, font, color}  (already exists)
→ API stores options JSON (opaque)
→ worker pipeline reads caps.style/font/color
→ build_captions_ass renders the (possibly new) engine kind with libass
```

No API/schema change beyond the web `captionStyle` enum + related TS type unions.

## Error handling / edge cases

- Unknown/removed style → worker already falls back to `karaoke`; web falls back to
  the default preset if a stored `captionStyleId` no longer resolves.
- Fonts: if a bundled font fails to load in the browser, the tile falls back to the
  CSS stack; burn-in is unaffected (libass reads the TTF directly).
- `clean` / `typewriter` ignore `color` (white); the picker hides the color swatch
  effect for those families.
- Disabled-until-script: chip is inert with no script, consistent with the others.

## Testing / verification

No formal JS/py test harness exists in the repo (verification = typecheck +
`py_compile` + manual/ffmpeg, per project convention).

- **Web**: `pnpm --filter @sentezy/web typecheck` clean. Manual: open composer →
  write script → open Altyazı → search + Filtrele + select → confirm chip updates
  and that navigating to create carries `caption` in `pending-create` and the
  wizard form reflects it.
- **Worker**: `python -m py_compile` clean. ASS-string assertions (ad-hoc script)
  for the 3 new kinds (correct `Style:`/`Dialogue:` lines). ffmpeg filtergraph
  validated where libass is available.
- **Follow-up (flagged, not blocking):** full end-to-end render test of the 3 new
  kinds on the Docker image (libass 5.x) — consistent with how the existing viral
  effects are tracked as "verified locally, not yet render-tested end-to-end".

## Out of scope (YAGNI)

- Per-user custom/saved caption styles.
- Editing caption position/size in this picker (already handled elsewhere).
- Uploading custom fonts.
- Any server-side style validation (options stay opaque JSON).
